# Accuracy workflow

How RuneCraft is being brought in line with OSRS: repeated rounds of *audit → implement → merge → push → CI release*.
This file and docs/ROUND_LOG.md are the shared memory of that loop. Update the round log (docs/ROUND_LOG.md) and the backlog here at the end of every round.

## The environment

- **Branch:** `claude/busy-cray-anf3uw` is the integration branch. Every push to it runs CI (`.github/workflows/build.yml`), which does three things:
  - builds the jar;
  - boots a real dedicated server (`tools/smoke_server.sh`), which force-loads Gielinor, checks every station block (strict), and summons bosses and monsters;
  - then runs the in-game self-test (`/rc selftest [filter]`, package `com.runecraft.selftest`) against a fake player (`platform.FakePlayer`): every menu opens, one recipe per menu is made, every quest is walked and completed, every minigame and raid runs, every boss ticks and is killed, every teleport lands on a safe spot, player data survives save/load. The job log ends with `SELFTEST n passed, m failed` and the `SELFTEST FAIL` lines (with stack frames); failures don't fail the job yet;
  - runs an xvfb client walkthrough (`tools/smoke_client.sh`, continue-on-error), which ends with `/rc selftest real minigame:,raid:,boss:` as the real, online player (the fake player is not in the player lists, so minigames, raid rooms and boss targeting skip it). Its `SELFTEST` lines and summary are printed in that step's log.

  Each green run publishes the jar to the `dev-latest` release.
- **Real compile without Gradle:** cloud sessions usually can't reach the NeoForge maven or Mojang, but CI publishes the full compile classpath as `neoforge-classpath.zip` on the `dev-latest` release, which does download. Unzip it into a scratch directory and run `bash tools/compile_full.sh <dir>` (about 15 s; must print `0 error(s)`). See docs/NEOFORGE_PORT.md, "Compiling locally".
  - `tools/loop/verify.sh` runs everything that does work offline:
    - core unit tests for the pure-Java `com.runecraft.osrs`;
    - `check_visibility.py`;
    - the best-effort `check_compile.py`;
    - `gen_assets.py` validation;
    - `gen_worldgen.py`.
  - Nothing is merged unless it prints `VERIFY OK`.
  - Set `TMPDIR` to a writable scratch directory if `/tmp` is shared.
- **Checking CI** (no auth needed for a public repo): `curl -s "https://api.github.com/repos/WreatheR6/RuneCraft/actions/runs?per_page=5"`.
  - Look for your commit's `head_sha`, then `status` and `conclusion`.
  - For failures, read the failed job's log (GitHub MCP `get_job_logs`) and search for `error:`.
- **Data sources:** the OSRS wiki itself is blocked from the sandbox, but GitHub and WebSearch work. `tools/loop/fetch_sources.sh <scratch>/sources` clones all of the repos below once (shallow) into a shared read-only cache; give agents that path instead of letting each clone its own. Never clone into the repo.
  - `Kiyogitpy/osrs-wiki-data`: raw wikitext dump (July 2026). The best general source.
  - `weirdgloop/osrs-dps-calc`: `cdn/json/monsters.json` and `equipment.json` (monster stats, max hits, equipment bonuses).
  - `Flipping-Utilities/parsed-osrs`: items, shops, recipes, GE prices and limits, wiki Lua modules (loot calculators, skilling charts).
  - `0xNeffarion/osrsreboxed-db`: item and monster dumps with drop tables (about Oct 2024).
  - `mejrs/data_osrs`: `NPCList_OSRS.json`, cache NPC spawns with tile coordinates.
  - `runelite/runelite`: skill-calculator `*Action.java` enums, slayer `Task.java`, timetracking `Produce.java`.
  - `skretzo/shortest-path`: transport TSVs with exact tiles.
  - `Zoinkwiz/quest-helper`: quest requirements and rewards.
  - `oldschoolgg/oldschoolbot`: cross-check only; it is often out of date.
- **Snapshots in tests:** when a source is machine-readable, commit a snapshot under `src/test/resources/osrs/` and add a test that diffs the mod against it. The equipment, skill-action, slayer and transport snapshots exist already.

## One round

1. Pick 4 independent scopes (see the backlog), so that parallel agents touch different files.
2. Start one sub-agent per scope, each in its own git worktree (`isolation: "worktree"`), with the **agent brief** below plus its scope. Number the scratch prefixes so they don't collide. Then give every branch an adversarial review (deep for game-logic changes, lighter for data-only diffs, which their diff tests already check) and a repair pass for what the review confirms.
3. When an agent reports, merge its branch with `NO_PUSH=1 tools/loop/merge_branch.sh <branch>` (push once after the round's last merge: every push starts a full CI run). It does the following:
   - Conflicts only in `src/main/resources`: takes the branch side, since those files are regenerated.
   - Code conflicts: exits 2. Resolve them by hand, keeping both sides' intent, then commit and run `tools/loop/verify.sh`.
   - Otherwise: verifies, commits the regenerated assets (and pushes unless NO_PUSH=1).
4. Wait for CI on the last commit. If it fails, read the log, fix the problem, verify and push again.
5. Update docs/ROUND_LOG.md and the backlog here, then commit and push (docs-only pushes don't start CI).
6. Every round ends committed and pushed with a fresh jar: confirm the `dev-latest` release body names the round's last code commit (`curl -s https://api.github.com/repos/WreatheR6/RuneCraft/releases/tags/dev-latest`). Docs-only commits don't trigger CI, and a newer push cancels an older run on the branch, so check the run of the last code commit finished green.
7. Free the disk: the session's writable allowance is about 40 GB and each worktree holds about 340 MB. After a round's branches are merged, remove their worktrees and branches (`git worktree remove --force .claude/worktrees/<wf>-N`, `git branch -D worktree-<wf>-N` once `git merge-base --is-ancestor` confirms the merge) and delete the round's scratch directories (`<scratchpad>/r<round>-*`). A full disk makes new worktrees fail and breaks agents mid-write.

Recurring conflict spots:
- `MenuType` (append new values last; the client uses ordinals);
- `Jewellery.wornExternal` lists;
- `DungeonsContentTest` dungeon count;
- shared hooks in `*Service` classes;
- `SpawnTable`.

## Agent brief (paste into every sub-agent prompt, then add the scope)

> You are auditing and improving a NeoForge 1.21.1 Minecraft mod (RuneCraft) that recreates Old School RuneScape (repo root = your working directory). Read docs/CONTENT_GUIDE.md and docs/WORKFLOW.md first. Pure-Java core lives in src/main/java/com/runecraft/osrs (unit-tested); Minecraft code in src/main/java/com/runecraft (Mojang names; compile it with tools/compile_full.sh against the classpath from the dev-latest release, see docs/WORKFLOW.md; CI also boots a dedicated server + a real client — mimic the existing 1.21.1 code).
>
> METHOD: compare the mod's data and mechanics in your scope against OSRS as documented on the OSRS Wiki. The wiki site is not reachable; use the GitHub data sources listed in docs/WORKFLOW.md (read them from the shared cache the coordinator gives you; clone anything missing into your scratch dir, never into the repo) and WebSearch ("osrs wiki <topic>") to confirm numbers. Prioritise: (1) things that are wrong (level, XP, stat, formula, drop rate, mechanic), (2) missing things that matter to gameplay, (3) polish. Fix them in code/data with tests; prefer committing a snapshot of a machine-readable source plus a diff test. Keep ids stable; don't duplicate ids across modules (grep first). Mark remaining guesses `// approx`. Append new enum values last (ordinals are saved or sent to the client).
>
> Rules: stay within your scope's files where possible; small edits to shared files are OK but keep diffs minimal (other agents work in parallel). A module may not reference another module's items (move shared items into CommonItems). Classes used from another package must be public. Don't touch tools/gen_assets.py, models/textures, structures or terrain unless your scope says so. If you add items/blocks/models, run tools/loop/verify.sh (it runs gen_assets validation).
>
> Compile: `check_compile.py` (inside verify.sh) cannot see errors in expressions involving Minecraft types. Also run `bash tools/compile_full.sh <classpath dir>` (the real compile against NeoForge; unzip neoforge-classpath.zip from the dev-latest release into a scratch dir first) and fix every error in files you touched before committing.
>
> Verify: while iterating, `RUNECRAFT_CLASSPATH=<classpath dir> TMPDIR=<your scratch dir> bash tools/loop/verify.sh --quick` (core tests + the real compile, ~1.5 min); before every commit the full `RUNECRAFT_CLASSPATH=<classpath dir> TMPDIR=<your scratch dir> bash tools/loop/verify.sh` must print VERIFY OK (it skips asset generation when nothing it reads changed, but always validates). Commit early and often: the container can restart and uncommitted work is lost. Commit on your branch (in stages if large). Do not push. Report: what you checked, what was wrong and fixed (before→after for important values), what's still missing or approximate, shared files touched, and the commit hash.
